# 測試先行

`CLAUDE.md` 開發流程第 3 條的細節。

- 規則引擎採測試先行：先寫測試並實際跑一次，確認它因為功能未實作而**斷言失敗**，再寫實作。
- 空殼回傳空值或預設值，不要 throw；import 錯誤或測試檔載入失敗不算。
- 空殼若會讓流程走到既有的內部錯誤 throw，就在測試中先加前置斷言，讓失敗出現在斷言上；測試 helper 檢查前提時也先用 `expect`，不要直接 throw。
- 版號等常數的提升也留到實作，空殼維持舊值，才有失敗證明。
- 期望值寫成常數或公開的參考值，不要用同一批空殼函式算出，否則兩邊都回傳預設值會讓測試空過。
- 若實作已先寫好，就暫時把實作改壞，確認測試會失敗後再改回；改壞後仍通過的測試代表斷言太弱，要補強或記成待補項。改壞後若先撞到既有的內部錯誤 throw，失敗不算出現在斷言上，換一種仍走得到斷言的改法（例：回傳錯的錯誤碼）。
- 失敗證明寫在 commit 訊息的 `Test-first:` 段落：測試名稱與失敗的斷言摘要（例：`expected 3, received 0`），每個新測試一行；`reviewer` 會檢查。
- 只改寫法、能證明新舊結果完全相同的改動（例：改照原版的運算順序）不會有修正前失敗的測試：在 commit 訊息與計畫檔寫出證明，測試改成涵蓋可能不同的邊界。
