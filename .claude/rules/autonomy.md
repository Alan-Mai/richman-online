# 自主決策

每個 ROADMAP 勾選項只停兩次：開頭（計畫經 reviewer 後給我核准）與結尾（里程碑）。中間的批次自行接續。

## 必須停下問我

先把進度寫回計畫檔再停。
- 素材／法律疑慮；推送（`/pre-push` 由我輸入）
- 逆向結果和我的記憶或錄影矛盾；需要非原版規則、「待確認」規則、原版未定義行為（第 7 條）
- 逆向超出計畫訂的時限仍查不到
- 新增依賴遇到 peer 範圍衝突，或只有發布未滿兩週的版本（第 10 條）
- 煙霧測試在本機跑不起來：先回報，不自行改用下載的瀏覽器
- 修改 `CLAUDE.md` 或 `.claude/` 底下的任何檔案
- 刪除檔案以外的不可逆操作（改寫歷史、`reset --hard`、丟棄 stash）
- reviewer 連續兩次不通過（附上兩次的回報）

## 自行決定，記在 `docs/REVIEW_QUEUE.md`

實作細節與非原版暫定值、範圍外的小修正（另開 commit）、時限內的逆向查證、測試與效能問題、和計畫的差異、ROADMAP 部分完成時改寫的內文（勾選留到里程碑）。照計畫或規則檔明寫的做法不用記。每筆和對應的改動放同一個 commit（REVIEW_QUEUE 與計畫檔的更新不算「另一件事」），格式見該檔開頭。理由與依據要先查證（例：「某處已能處理」先搜尋確認、「既有測試沒涵蓋」先讀測試）；查不到的寫成推測。

## 審查

用 Agent 工具呼叫 `reviewer`，只給輸入、不轉述過程：計畫給我核准前用 `plan <計畫檔>`；每批 commit 完成後、開始下一批前用 `batch <base>..<head> <計畫檔>`。不通過就用新 commit 修正後重審。改到 `apps/client` 的批次，審查前先跑 `pnpm -F smoke shot -- --out <scratchpad>` 並自己看截圖。reviewer 的「建議」屬於上面「自行決定」的範圍時，直接處理：另開 commit、重審，不必先問；只改測試資料、措辭或過時文字的記在計畫檔進度，其餘記進 REVIEW_QUEUE。範圍小的項目可把幾批合併審查，但里程碑前至少一次 `batch` 涵蓋計畫核准後的全部改動。

## 里程碑

勾選項做完時一次交付：🎮 試玩清單（附煙霧測試截圖路徑）、REVIEW_QUEUE 待審項（補上 commit hash）、規則提案（`/wrap-up` 第 4 步的分類）、待我確認的 ROADMAP 勾選，最後提醒我輸入 `/wrap-up`。我試玩完成前不提醒推送。回饋的修正用新 commit。

## 接續

計畫檔開頭維持 `## 接續狀態`：目前批次、下一個動作、未 commit 的工作、待審筆數；每個 commit 後更新。context 壓縮、換 session，或我說「繼續」或下面這句開場時，先讀計畫檔的接續狀態再動手：

```
讀進行中計畫檔的接續狀態，繼續做
```
