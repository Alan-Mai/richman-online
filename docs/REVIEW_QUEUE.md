# 自主決策待審清單

Claude 自行決定、需要使用者在里程碑時審查的判斷（規則見 `.claude/rules/autonomy.md`）。

- 每筆和對應的改動放在同一個 commit，「commit」先寫 commit 標題，里程碑交付時再補上 hash。
- 「依據」寫檔案:行、`DECISIONS.md` 條目、逆向位址；不寫原版數值、名稱或反編譯內容。
- 審過後：同意的刪除（影響架構的轉寫成 `DECISIONS.md` 條目），不同意的另開修正 commit 後刪除。

格式：

```
### YYYY-MM-DD · <commit 標題>
- 類別：實作細節｜範圍外修正｜逆向查證｜測試與效能｜計畫差異｜ROADMAP 改寫
- 判斷：做了什麼決定
- 理由：為什麼這樣做、考慮過的替代做法
- 依據：檔案:行、文件條目、逆向位址
```

### 2026-10-23 · docs(rules): 設定畫面的預設檔位與選項文字（逆向）
- 類別：計畫差異
- 判斷：新增批次 0b：`tables.json` 升 v3，匯出天數上限每檔的選項文字（執行檔內的字串表），客戶端匯入後照原版顯示這些文字。淨值目標照原版顯示金額（起始資金 × 倍數），起始資金不加千分位。
- 理由：原版天數上限不顯示數字，而是每檔一段文字；字串是執行檔資料，不能寫進倉庫，比照其他表在本機匯出。另一種做法是自己顯示「N 日」，但那是非原版的呈現（GAME_RULES 寫作慣例第 17 行不允許直接自訂）。淨值目標倍數為 0 時原版也是一個固定字串，這個不匯出、照專案慣例用自己的措辭放 i18n：它是單一的固定訊息，和其他介面文字一樣；天數上限是 6 段內容無法由數值推出的文字，所以要匯出。
- 補充（`feat(extract): tables.json v3 匯出天數上限的選項文字`）：匯出時每段文字限 64 bytes、shared 驗證 1–64 字，都是非原版的合理上限（本機副本每段 2–3 字）。
- 依據：`notes.md` 步驟 11（0x00404778、0x004046a2、0x0046316e）；`GAME_RULES.md` 第 1 節「原版設定畫面的起始資金、天數上限、淨值目標」。

### 2026-10-23 · feat(client): 設定表單可依原版檔位產生天數上限、淨值目標與起始資金
- 類別：實作細節
- 判斷：淨值目標的選項文字用精確的「起始資金 × 倍數」。原版以 32 位元 IMUL 相乘，乘積超過 2^31 − 1 時會溢位成別的數字；本專案不模擬溢位。
- 理由：引擎判斷淨值目標時也用精確乘積（`engine.ts` 的每日檢查），文字和判斷一致；本機副本所有組合的乘積都在 32 位元內（scratch 檢查只印布林），兩種做法顯示相同。若要完全照原版，引擎與文字都要改成 32 位元乘法，屬另一項。
- 依據：`notes.md` 步驟 11（0x004046a2）；`packages/shared/src/engine.ts` 的淨值目標判斷。
